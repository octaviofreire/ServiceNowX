# ADR — Aula 04: Observer notifica todos os assinantes

## Contexto

O Achado 5, registrado na Aula 03, apontava que o `TicketPublisher` guardava
um único observer (`private TicketObserver observer`) e que o segundo
`subscribe()` substituía o primeiro — fazendo com que apenas o último
observer inscrito fosse notificado.

Ao revisar o código-fonte de fato nesta aula, constatou-se que a estrutura
já havia sido alterada para `List<TicketObserver> observers`, mas o método
`publish()` ainda referenciava uma variável `observer` (singular) que não
existia mais na classe — um resquício da versão anterior. Isso não apenas
mantinha o bug (notificação incompleta), como impedia o código de compilar.

## Decisão

Corrigir o método `publish()` para percorrer a lista `observers` com um
laço `for-each`, chamando `update()` em cada observer inscrito, em vez de
referenciar uma variável única inexistente.

## Antes / Depois

**Antes:**
```java
public void publish(String id, String event){
    if(observer != null) observer.update(id, event);
}
```
*(erro de compilação — `observer` não estava declarado na classe)*

**Depois:**
```java
public void publish(String id, String event){
    for (TicketObserver observer : observers) {
        observer.update(id, event);
    }
}
```

## Consequência

**Positivo:**
- O sistema volta a compilar.
- Todos os observers inscritos (`subscribe()`) são efetivamente notificados
  a cada evento publicado, corrigindo o comportamento esperado do padrão
  Observer.
- A classe respeita melhor o princípio Open/Closed: novos observers podem
  ser adicionados via `subscribe()` sem exigir alteração no `publish()`.

**Negativo:**
- Nenhum relevante identificado. Mudança de baixo risco, sem alteração na
  interface pública da classe (`subscribe()` e `publish()` continuam com
  a mesma assinatura).

## Observação sobre o diagnóstico

O problema real encontrado no código diferiu da hipótese original da
Aula 03 (que descrevia substituição de observer, não ausência de variável).
Isso reforça a importância de validar achados lendo o código atual antes
de aplicar uma correção, em vez de assumir que a descrição anterior está
exatamente certa.
